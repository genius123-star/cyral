# 模型中转站自动适配

## 目标

Cyral 允许用户只填写 Base URL、API Key 与模型名称；供应商名称为可选备注，接口协议默认自动检测。保存配置时，后端验证并保存真正可用的 URL 与协议，避免 `/v1`、端点路径或模型厂商名称造成误配置。

## 约束与假设

- Base URL、API Key、模型名称必填；供应商名称可留空。
- API Key 仅保存到 Windows 凭据库，不写入 SQLite 或日志。
- 自动探测最多使用一个极短回复，可能产生一次极低的供应商费用。
- 探测按顺序停止在第一个成功组合，不并发重复请求。
- 鉴权、余额和模型不可用错误直接返回，不继续尝试，以免掩盖真实问题。
- 路径不存在、返回网页或响应格式不兼容时，才尝试下一个候选组合。

## 设计

候选顺序为：用户原始 URL 的 Chat Completions、补全 `/v1` 后的 Chat Completions、用户原始 URL 的 Responses、补全 `/v1` 后的 Responses。若 URL 已包含 `/v1` 或完整端点则去重。高级设置选择具体协议时，只探测该协议的候选 URL。

保存流程：校验必填字段 → 构造去重候选 → 发送最短探测请求 → 分类错误 → 保存成功的规范化 URL、协议与可选备注 → 将 Key 写入 Windows 凭据库。运行时仅在 404、网页正文或无法识别的响应格式下重新探测一次；401/403、余额不足、限流和模型不存在不重试。

## 决策记录

- 供应商名称不参与路由，仅作可选备注；因为中转站可以代理任意厂商模型。
- 默认自动检测，保留高级协议覆盖；兼顾普通用户与特殊中转站。
- 采用保存时探测并保留运行时一次兜底；相比纯字符串补全，它能同时验证 URL、Key、模型和协议。
- 不根据模型名称猜测供应商；模型 ID 无统一命名规范。
