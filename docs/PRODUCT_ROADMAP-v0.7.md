# Cyral v0.7 产品完善与公开发布路线

状态：已批准，进入实施  
日期：2026-09-28

## 1. 产品主线

Cyral 是一个本地优先的长期桌面伙伴。产品闭环固定为：

> 观察当前状态 → 形成跨天记忆 → 在合适时机主动关心 → 帮助用户处理少量高价值事务

所有新需求必须直接增强这条闭环，并同时满足可解释、可撤销、可审计三个条件。Cyral 不发展为通用桌面 Agent。

## 2. 当前阶段范围

### 纳入

1. 应用生命周期、托盘恢复、休眠恢复和任务调度的稳健性。
2. 记忆来源展示、纠正、暂不提及、静音与彻底删除。
3. 基于跨天主题、当前活动和待办状态的自然主动关心。
4. 由白名单状态机控制的上下文动画选择。
5. 后台邮件生成、审核和由用户最终确认发送。
6. 经过隐私、密钥与素材授权审计的 GitHub 公共版本。

### 后续表现层能力

以下能力保留兼容位，但不在本阶段提前实现通用插件系统：

- 动画资源与播放策略优化。
- 主体颜色设置。
- Cyral 形象一键切换。

动画与形象资源以后统一通过版本化清单描述；业务逻辑只引用语义标识，不依赖具体文件路径。

### 明确排除

- 通用网页自动化和浏览器代操作。
- 任意文件编辑、删除、下载或自动提交。
- 即时通信自动发送。
- Live2D/VRM、MOD 市场和第三方代码插件。
- 常驻麦克风监听和云端账号同步。
- 由模型自行执行发送、提交、删除等决定性操作。

## 3. 实施顺序

### P0：可信运行

- 单实例启动与重复启动唤回。
- 托盘恢复、屏幕越界复位和悬浮球恢复。
- Windows 休眠/唤醒后的调度重建与任务去重。
- 异常退出恢复和脱敏诊断导出。
- 数据库迁移、备份和失败回滚验证。

完成标准：连续 50 次启动、退出与托盘恢复无失联；休眠恢复后提醒和主动对话不重复。

### P1：可控记忆与自然陪伴

- 为记忆保存来源、首次出现时间、最后出现时间、可信度和状态。
- 删除记忆时同步清理检索记录及关联关系。
- 主动话题先由确定性规则筛选，再由模型负责自然表达。
- 统一安静时段、冷却时间和一次性触发凭据。
- 动画通过语义标签、优先级、冷却时间和兜底项选择。

完成标准：七天连续验收中，纠正立即生效、删除后不再召回、主动对话不机械汇报工具名称。

### P2：后台邮件

状态机固定为：

> 收集信息 → 后台生成 → 等待审核 → 用户点击发送 → 成功 / 失败 / 取消

- 最多追问三轮。
- Gmail、QQ、网易和自定义邮箱共用最小邮件提供方接口。
- 凭据只进入 Windows Credential Manager。
- 审核卡片完整展示收件人、主题、正文、附件与发件账户。
- 模型没有发送权限，未经用户最后点击不得产生网络发送。

完成标准：四类邮箱均通过生成、取消、失败重试和人工发送测试；未经确认的实际发送数为 0。

### P3：公开发布

- 审计工作区和完整 Git 历史中的密钥、个人路径、数据库、日志、截图和第三方素材。
- 不直接公开包含旧 Chrome 原型和未确认授权素材的现有历史。
- 建立经过净化的公共历史和明确的素材授权清单。
- 补齐 README、LICENSE、PRIVACY、SECURITY、CONTRIBUTING、构建说明和问题模板。
- GitHub Actions 运行前端测试、Rust 测试、格式检查、静态检查和 Windows 构建。
- 从干净 Windows 环境生成 NSIS/MSI、校验和与版本说明。

完成标准：公共仓库密钥泄露为 0；所有公开素材均有授权记录；全新 Windows 环境可按文档完成构建、安装和卸载。

## 4. 强制技术边界

1. 模型只提供语义判断与自然语言，不直接选择资源路径，不持有决定性操作权限。
2. 所有后台任务必须有持久化状态、取消入口、幂等键和明确终态。
3. 工具调用、模型推理和兼容规划不得进入用户可见正文。
4. 只有底层返回可验证成功凭据后，界面才能显示“已发送”“已创建”或“已打开”。
5. 不为当前路线再引入第二套 Agent 框架、数据库或包管理器。
6. 自动化测试和真实桌面验收分别记录，不能互相替代。

## 5. 发布闸门

以下任一条件未满足，禁止上传公共 GitHub 仓库：

- 代码许可证尚未确定。
- 角色、动画、字体或图片授权不完整。
- Git 历史仍包含凭据、个人数据或未授权素材。
- 干净环境无法复现构建。
- 隐私说明与应用真实行为不一致。
